### 2.3 状态机（五状态）
- [x] 状态定义：FORWARD / SLOW / LEFT / RIGHT / STOP
- [x] 决策函数按规则排序实现（R5>R1>R2>R3>R4），每条输出 rule 与 why（当前状态 × 输入类别 → 下一状态），别写成几百行 if-else
- [ ] 输入类别归一化：`(雷达前距分档, 雷达左距, 雷达右距, 视觉障碍有无, 视觉目标方位, 数据是否新鲜)`
  - 距离分档示例（阈值要队内定）：<0.5m 危险 / 0.5~1.2m 警惕 / >1.2m 安全
  - 验收：任意输入组合都能查到确定的下一状态（无死锁、无未定义转移）

### 2.4 五条融合规则（逐条实现，逐条测试）
- [x] **R1 双确认加险**：视觉有障碍 + 雷达同方向近距离 → 两者都触发 SLOW/STOP 中最保守的
- [x] **R2 视觉优先**：视觉有障碍但雷达无有效数据（null）→ 仍按视觉保守动作，不许因雷达没数据就放行
- [x] **R3 雷达单源谨慎**：视觉无 + 雷达近距有目标 → 连续 N 帧（N=3 起）确认才减速/停；单次回波只报警不急转
- [x] **R4 转向决策**：往哪边转 = 视觉目标方位 + 左右可通行空间，谁低听谁的；**不是**哪边雷达距离大就转哪边
- [x] **R5 失效即停**：雷达超时 / Vision JSON 过期 / Status `fault:true` → 无条件 STOP
  - 验收：每条规则一个独立测试用例（tests/ 里），`python -m pytest` 全绿

## 风险与备案

| 风险 | 影响 | 备案 |
|---|---|---|
| 视觉延迟/丢帧导致融合滞后 | R2/R4 失效 | Vision 帧带时间戳，过期直接按无效处理 |
| 雷达被遮挡污染（手、线缆） | 误停 | R3 的 N 帧确认 + 扇区滤波 |
| TCP 在比赛现场断 | 车失控 | watchdog + 徐侧也要有本地兜底（PS 端检测超时自动停） |
| 时间不够全做完 | 丢分 | 优先级：2（状态机）> 4（TCP+安全）> 5（联调）；仿真全通过 Priority 底线 |
