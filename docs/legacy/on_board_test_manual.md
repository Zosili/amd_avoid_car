# 零、一条铁律

**一次只加一个变量。**

上板测试最贵的错误不是"某个模块坏了"，而是"三个模块一起接上，然后不知道是谁坏的"。
所以下面的阶段是**严格串行**的，每一阶段只新引入一样东西，其余全部用 mock 顶着。
某阶段没过，**就地停下**，不许带着问题往下走 —— 带着问题走，后面每一个现象都是两种原因的叠加，
排查成本会指数上升。

判据也很明确：**每阶段都有"一句话能说清的成功标志"**。说不清就是没验完。

## 一·五、一个人也能验的四层（郑的自测路径）

**不用等徐，也不用等欧阳。** 你的代码能不能跑、雷达好不好使，分四层验，
每层只依赖上层的结论，缺哪层就停在哪层：

| 层 | 需要什么 | 验出什么 | 时间 | 命令 |
|---|---|---|---|---|
| **L0** | 只有雷达 + 你的电脑 | 雷达硬件、协议解析、决策逻辑 | 10 分钟 | `python preflight.py --port COM5` |
| **L1** | 板子（**不需要 bit**） | Python 环境、依赖、串口权限 | 20 分钟 | 板子上 `python3 preflight.py --no-radar` |
| **L2** | 板子 + 徐的 bit | AXI 电机通路 | 10 分钟 | 板子上 `python3 preflight.py` |
| **L3** | 再加欧阳的机器 | 视觉链路 | 20 分钟 | `--vision udp` |

**关键认知：L1 不需要 bit。** PYNQ 的 Linux 是 SD 卡上的镜像，跟 PL 里有没有逻辑无关。
所以"我的代码能不能上板"这个问题，**现在就能回答**，只要板子能开机。

### 统一入口：`preflight.py`

```bash
# L0：PC 上，雷达插 USB
python preflight.py                       # 自动找串口
python preflight.py --port COM5 --secs 7  # 指定口，读 7 秒
python preflight.py --no-radar            # 雷达不在手上，只查环境

# L1：板子上，雷达还没接
python3 preflight.py --no-radar

# L2：板子上，全查
python3 preflight.py --port /dev/ttyUSB0 --secs 7

# 结果存 JSON 发给队友
python3 preflight.py --json pf.json
```

输出是一张检查表，`[FAIL]` 后面直接跟修法。**照着改完重跑，直到 0 fail 再上板。**

### 雷达"正常工作"的量化判据

别说"感觉有数据"。下面五条同时满足才算正常（D6 实测基准）：

| 指标 | 正常值 | 不对说明什么 |
|---|---|---|
| 帧率 | **≈163 Hz**（实测 171 正常，因为转速 10.7 圈/s 略高于标称 10.2） | <50Hz = 丢帧严重，换 FT232 转接板；波特率错会掉到 0 |
| 一圈覆盖 | **360°** | <180° = 雷达没在转（供电电流不够 / 被卡住 / 发过停止指令） |
| 校验通过率 | **>95%**（本机实测 100%） | 低了就是串口误码：线太长、离电机电源线太近 |
| 有效点比例 | **>30%**（室内通常 >90%） | 极低 = 镜片脏 / 全超 12m 量程 |
| 前扇区点数 | **≈33 个/圈**（30° ÷ 0.9° 步进） | 远低于此 = 正前方被自己的外壳/线束挡住，或 `ZERO_OFFSET_DEG` 要标定 |

⚠️ **必须累积一整圈 400 点再统计**（`LiveRadarProvider` 就是这么做的）。
拿单帧（25 点、22.5°）统计会得到"前扇区 0 点"的假故障 —— 那是统计口径的错，不是雷达坏了。

### 三扇区读数怎么读

`前=0.15m 左=0.17m 右=0.46m` 这种**三面都是几十厘米**的读数，
说明雷达被东西包着（放桌上、贴着显示器、有外壳）。
**这不是故障，但测不出真实性能** —— 拿到空旷处对着 3~5m 外的墙再跑一次。

正常空旷场景应该是：某一面 2~5m（对着墙），另外两面是 12m 超量程的"无回波"。

### L2 的额外判据（AXI）

```bash
# 板子上，PL 状态
cat /sys/class/fpga_manager/fpga0/state     # operating = bit 在
```

`preflight.py` 会自动读 `MMIO(0x43C00000, 0x18)`：

| 读到 | 含义 |
|---|---|
| `0xFFFFFFFF` | **地址上没人应答** —— bit 是旧的 / 地址不对 / motor_axi 没接 M_AXI_GP0 |
| `0x0` | 有应答但状态位全 0 —— 正常初始态，写 `0x00=1` 使能后应出现 bit2 |
| 其他 | 有应答，PL 里的电机控制器活着 |

# 三、现场接线（顺序不能错）

**断电状态下接线，最后才上电。** 带电插拔杜邦线，很容易把 5V 灌进 3.3V 的 IO。

```
① SD 卡插进板子（带镜像那张）
② 雷达四根线接 UART
     雷达 黄(5V) ── 板子 5V
     雷达 白(GND)── 板子 GND
     雷达 红(TXD)── 板子 RXD     ← 必须交叉
     雷达 黑(RXD)── 板子 TXD
③ 电机驱动板接 PL 的 PWM/方向引脚（按徐的 xdc）
④ 网线：PL 口 → 欧阳的笔记本
         PS 口 → 郑的笔记本（或都进交换机）
⑤ USB 线：板子 console 口 → 郑的笔记本
⑥ 最后插 12V 电源
```

⚠️ **雷达是 5V 供电，但它的 TXD 输出电平也要确认**。D6 是 5V TTL 输出，
直接接 Zynq 的 3.3V UART 引脚，**长期有风险**（Zynq 的 IO 不是 5V 容忍）。
现场先用，但心里要有数：如果 UART 口烧了，就是这个原因。稳妥做法是串一个 1kΩ 电阻。

**上电后 30 秒内看 console**（115200 8N1），正常会刷一大段启动日志到 `xilinx@pynq:~$`。
console 什么都不出 = SD 卡没插好 / 镜像坏了 / 启动模式拨码不对（这三个按顺序查）。

## 阶段 1 · 只验雷达（郑主导，10 分钟）

| | |
|---|---|
| **谁** | 郑操作，徐不用管 |
| **只验什么** | 串口能收到合法帧 |
| **前置** | 阶段 0 过 |
| **命令** | `ls -l /dev/ttyUSB*`<br>`python3 run_on_board.py --port /dev/ttyUSB0 --motor mock` |
| **成功标志** | 每 100ms 打一行，`前=` 后面是**数字**不是 `None`，且人走过时数字会变 |
| **失败先查** | 见下面三行 |

```
没有 /dev/ttyUSB0        → 雷达没上电 / USB 转接板没插 / 换个口再 ls
有设备但 前=None         → TXD/RXD 没交叉。雷达红接板子 TXD 是错的，要接 RXD
有数字但一直不变         → 雷达在转吗？用手挡一下前面，数字不动就是数据没更新
```

**雷达摆位**：先别装车，平放桌上，正前方 1 米放个纸箱。手动挪箱子，看 `前=` 跟着变。

## 阶段 2 · 只验视觉（欧阳 + 郑，20 分钟）

| | |
|---|---|
| **谁** | 欧阳在 PC 上跑推理，郑在板子上看接收 |
| **只验什么** | 视觉结果能跨机器进到板子的决策程序 |
| **前置** | 阶段 1 过（雷达已经在跑）；PS 网口 IP 配好 |
| **命令** | 板子上：`sudo ip addr add 192.168.1.20/24 dev eth0`（临时）<br>板子上：`python3 run_on_board.py --port /dev/ttyUSB0 --vision udp --motor mock`<br>欧阳：`target_ip` 指向 `192.168.1.20` |
| **成功标志** | 收包频率 ≥7Hz、坏JSON=0、拒收=0；人走近时规则号从 `OK` 变 `R2` |
| **失败先查** | 见下面 |

```
一个包都收不到   → 先 ping 192.168.1.20（从欧阳机器）。不通就是 IP 段不对或网线插错口

有包但全拒收     → 字段名对不上。拿 integration/contract.py 的 detections_to_vision() 逐字段核

规则号一直 R5    → 视觉数据超时。看日志里 vision_timeout_ms 和实际间隔
```

⚠️ **这一步如果欧阳的机器没到，不要等。** 郑先用 `--vision mock` 跳过，
把阶段 3（电机）先做掉 —— 电机是徐的硬件，等不起。

## 阶段 3 · 只验电机（徐 + 郑，20 分钟，**车必须架空**）

| | |
|---|---|
| **谁** | 徐接线和量电，郑敲命令 |
| **只验什么** | AXI 寄存器能控制轮子 |
| **前置** | 阶段 0 过（PL 里有 motor_axi） |
| **命令** | 见下面 |
| **成功标志** | 左轮转、右轮转、写 0 停、**停止喂心跳 300ms 自动停** |
| **失败先查** | 见下面 |

```python
# 板子上，直接 MMIO，不依赖郑的代码
from pynq import MMIO
m = MMIO(0x43C00000, 0x1000)
m.write(0x00, 1)        # 使能
m.write(0x04, 500)      # 左轮 50%
m.write(0x0C, 1)        # 心跳
print(hex(m.read(0x18)))   # 期望 0x4（bit2=使能中）
```

```
读到 0xFFFFFFFF        → PL 里没有这个 AXI 从机。bit 没烧对 / 地址不是 0x43C00000
读到 0 但轮子不转      → 驱动板没电，或 PWM 引脚没接对。上万用表
轮子转但方向反         → 改 motor_axi.v 里 in1/in2 顺序，不用改 xdc
转一下停一下           → 心跳没喂。郑的代码每周期要写 0x0C
```

🚨 **车必须架空（轮子离地）**。第一次给电永远不要放地上 —— 车窜出去撞坏东西是 5 秒的事。

**这一步过了，整条链路才第一次闭环。**

## 阶段 4 · 联合跑（三人，30 分钟，**仍然架空**）

| | |
|---|---|
| **谁** | 三人都在，郑操作，欧阳站摄像头前，徐管电 |
| **只验什么** | 三个模块同时活着，规则号能正确切换，电机跟着变 |
| **前置** | 阶段 1/2/3 全过 |
| **命令** | `python3 run_on_board.py --port /dev/ttyUSB0 --vision udp --motor axi` |
| **成功标志** | 下面四条**同时**成立 |
| **失败先查** | 见下面 |

**四条验收**：

1. `前=` 是真实数字（雷达活着）
2. 收包 ≥7Hz、拒收 0（视觉活着）
3. 欧阳在镜头前左右走 → 规则号在 `OK / R2` 之间切，不是一直同一个（决策活着）
4. `Ctrl-C` → 电机**立刻**停，不是滑行（安全链活着）

**四条里有任何一条不成立，就退回对应阶段重做**，不要试图在联合状态下调。

```
一直 R5        → 视觉没到。回阶段 2
前=None        → 雷达断了。回阶段 1（常见：跑久了 USB 掉线，重新插）
规则号不动     → 决策收不到数据。加 --verbose 看每周期输入
Ctrl-C 不停    → 安全链断了。立刻拔电源，然后查心跳和看门狗
```

⚠️ 建议**同时开两个终端**：一个跑主程序，一个 `tail -f integration/logs/board_*.jsonl`。
屏幕上只显示最后一行，日志里才有完整过程。

| 现象 | 最可能原因 | 找谁 | 第一条命令 |

| 轮子不转但寄存器正常 | 驱动板没电 | 徐 | 万用表 |
| `Ctrl-C` 不停 | 看门狗没生效 | 徐 | 拔电源，查心跳 |
| 跑几分钟后全挂 | USB 掉线 / 内存泄漏 | 郑 | 看 `dmesg`、看进程内存 |

# 七、加速技巧：热换 bit，不重烧 SD 卡

徐改一次 Verilog 要 15~40 分钟综合，如果每次都拔卡重烧，一天只跑得了几轮。
**PYNQ 支持运行时加载 bitstream**：

```python
# 板子上，把新的 .bit 放到 /home/xilinx/ 后
from pynq import Overlay
ol = Overlay("/home/xilinx/design_1.bit")
```

scp 一个 `.bit`（几百 KB）几秒钟，比重烧 SD 卡快两个数量级。

**但有两个前提**：

| 前提 | 说明 |
|---|---|
| PS 侧的硬件设计不能变 | Overlay 只重配 PL。如果徐改了 Block Design 里 PS 的配置（MIO、DDR、时钟），必须重烧 |
| `.hwh` 要一起带 | 不带的话 `Overlay` 能加载但拿不到 `ol.xxx` 属性名。郑的代码用裸 `MMIO` 就不受影响 |

**结论**：郑的 `run_on_board.py` 用 `MMIO(0x43C00000, 0x1000)` 裸访问是对的 ——
不依赖 Overlay 的属性名，徐换 bit 时郑一行不用改。
