## 1. `radar_bringup` —— D6 激光雷达接入与体检

| 项 | 内容 |
|---|---|
| 解决什么 | 新板子/新雷达接上后，10 分钟内判断「线接对没有、协议解对没有、读数可信不可信」，而不是靠肉眼看点云 |
| 入口 | `host/app/radar_console/radar_helper.py probe --port <COMx> --secs 5` |
| 离线替代 | `host/app/d6_tools/d6_frame_analyze.py`（用仓库内 97 022 B 抓包，不接硬件也能验证解帧） |
| 输出 | 帧率、坏帧数、有效点率、距离 min/中位/p90/max、12 扇区与三扇区距离 |
| 已验证 | 2026-10-31 四次采样：169.5 帧/s、0 坏帧、有效点 92.9 %（桌面）/98.1 %（手举空中）；与 10-25 基线一致 → 雷达本体健康 |
| 失效条件 | ① 桌面/墙体围住时会读到 0.2 m 的假近距（必须换开阔环境复核）；② 波特率不是 230400 时帧率会异常；③ 换固件后 `M&T` 位定义若变，解帧需重验 |
| 复用结果 | 换第二颗 D6（或同系列 D4）时只需改 `--port`/`BAUD`；同一套判据在 PC 与板子上一致（`preflight.py` 复用同一 provider） |

## 2. `three_end_bringup` —— 三端（视觉 / 决策 / 电机）联调

| 项 | 内容 |
|---|---|
| 解决什么 | 三个人的代码还没凑齐时，也能把「视觉说左边有人 → 决策往右打 → 电机收到 pwm」整条链路先跑通并留证据 |
| 入口 | `cd host/app && bash joint/_run_it.sh person_left`（假电机 5001 + 板入口 + 假视觉 5000） |
| 变体 | `_run_net.sh`（带 5002 监控）、`_run_monitor.sh`（只验广播）、`_run_live.sh`（真雷达 + 假电机） |
| 判据 | 终端出现 `R4 RIGHT vision=left L=1.0 R=1.0` 这类行；`motor.csv` 里 `pwm_l≠pwm_r` 且方向与 `in1..in4` 一致 |
| 已验证 | 10-26 联调成型；2026-10-31 复算 15 份日志：决策周期 P99 101 ms、未命中 0/97 |
| 失效条件 | ① 视觉发送频率 < 7 Hz 时车会一顿一顿（`vision_timeout_ms=300` 硬约束）；② 电机侧不回 Status 时 500 ms 后强制 STOP（看起来像"发不出去"）；③ 端口 5000 的 TCP/UDP 两套实现不能同时起 |
| 复用结果 | 换成机械臂/云台时只替换 `contract.control_to_diff()` 之后的一段，决策与协议层不动 |

## 3. `fpga_bit_repro` —— 视觉链路 FPGA 工程复现与资源/时序取证

| 项 | 内容 |
|---|---|
| 解决什么 | 换机器/换 Vivado 版本后能重新出 bit，并留下资源与时序证据（3.2.5.1(2) 要求） |
| 入口 | `fpga/build/` 的 tcl + `fpga/report/*.rpt` 原始报告 |
| 判据 | 时序约束全部满足（WNS > 0）、LUT/FF/BRAM/DSP 与报告一致 |
| 已验证 | Vivado 2025.2 / `xc7z020clg400-2`：LUT 2.19 %、FF 1.07 %、WNS **+1.096 ns** |
| 失效条件 | ① 换器件或改 `CLK_HZ` 参数后 PWM 频率与看门狗时间一起偏；② 换 Vivado 大版本时 IP 需重新生成（`.xci` 版本锁）；③ 报告是「某一次实现」的快照，改了 RTL 必须重跑 |
| 复用结果 | 同一套 build 流程可直接搬到 KR260/PYNQ-Z2 的同类视觉链路（改器件与约束即可） |
